# Архитектура VECTOR PDF 0.3

Вместо C++-обвязки использованы PySide6 и штатные Python-обёртки нативных
библиотек. PDFium и QPDF выполняют интерпретацию графики, рендер и разбор PDF в
нативном коде. PySide6 предоставляет Qt Widgets без браузерного процесса.
Python связывает интерфейс, кеш и правку потоков.

| Модуль | Назначение |
| --- | --- |
| `document.py` | Источник, приватный снимок, версии правок, Undo/Redo, journal/recovery и метрики |
| `render.py` | Выделенный последовательный worker PDFium, тайлы, миниатюры, общий бюджет кешей |
| `object_index.py` | Ленивый индекс `Tj`, графическое состояние, clipping/цвет, R-tree |
| `writer.py` | Проверка глифов/подписей, безопасная замена, QPDF-запись и валидация результата |
| `fonts.py` | Декодирование шрифтов, проверка реальных глифов, subset/fallback |
| `canvas.py`, `ui.py` | Вид, интерактивный слой, свойства, вкладки, сохранение, recovery, About/логи |
| `updater.py`, `__main__.py` | Подписанный manifest, health-check, rollback, safe mode, readiness handshake |

## Просмотр

PDFium работает в одном выделенном потоке, включая освобождение дескрипторов.
В режиме просмотра пространственный индекс не строится. Полотно запрашивает
видимые тайлы до 512 × 512, сначала ближайшие к центру. Масштаб дискретизирован
шагом √2 с учётом DPI. Тайлы рисуются от низкого разрешения к высокому; кеш
использует `peek()` для проверки без искажения статистики. На вкладку и на
процесс действуют ограниченные бюджеты; неактивные вкладки обрезаются.

## Правка и графическое состояние

Индекс строится по запросу на конкретном листе. Для каждого `Tj` сохраняются
поток, порядковый номер, байты, матрицы, шрифт, fill color, clipping и признак
безопасности. Текст в Form XObject не редактируется. `gap()` не объединяет
разные цвета, clip, ресурсы или графические контексты; порог пробела зависит от
реального `space` шрифта.

Замена встроенным шрифтом разрешена только после проверки cmap/CID→GID и
только для одного show-операнда. Для остальных случаев исходные `Tj`
очищаются, а один самодостаточный текстовый блок добавляется в конец страницы
вне исходного CTM/clip. Поэтому:

- позиции соседних `Tj` не накладываются;
- перемещённый текст виден, даже если исходный был обрезан;
- цвет задаётся явным `rg` и не наследуется от последующих операторов;
- z-order результата — верхний слой, что совпадает с предпросмотром.

Текст внутри clipping остаётся редактируемым с предупреждением. Текст с
неподдерживаемым цветовым пространством, `gs`, render mode или небезопасной
матрицей помечается read-only с причиной. Это осознанная политика: лучше
отказать, чем сохранить невидимый или перекрашенный текст.

## Запись

Содержимое изменённого потока копируется и правится по байтовым смещениям QPDF.
Нетронутые страницы сохраняют исходные потоки. Для нового шрифта копируется
словарь ресурсов затронутого листа. QPDF работает с отключённой перекомпрессией
исходных потоков; замена выполняется через временный файл, `fsync` и
`os.replace`.

Перед заменой результата:

1. PDF переоткрывается с `attempt_recovery=False`;
2. проверяются подписи, предупреждения QPDF, число страниц и геометрия;
3. сравниваются сырые потоки нетронутых страниц;
4. PDFium переоткрывает документ и проверяет новый текст;
5. для небольших документов выполняется полный QPDF syntax check;
6. существующая цель копируется в `.bak`.

Глубокий QPDF-токенайз 17-мегабайтного CAD-потока занимает секунды, поэтому он
ограничен бюджетом; на больших чертежах всегда выполняются остальные проверки,
а QA отдельно прогоняет полный QPDF/raster на реальном файле. Это компромисс
между безопасностью и отзывчивостью; он зафиксирован в `BENCHMARKS.md` и
`KNOWN_LIMITATIONS.md`.

Источник при открытии копируется в приватный workspace-снимок. Индекс, рендер и
сохранение используют снимок, поэтому изменение/удаление исходника не делает
уже сделанные правки несохраняемыми. Сам исходный файл не перезаписывается:
совпадение цели с исходником/снимком отклоняется до записи.

## Undo/Redo, recovery

Каждая успешная правка создаёт новую временную версию PDFium; `Document`
хранит снимки состояния и курсор. `journal.json` в workspace фиксирует
последнюю версию, исходник и timestamp. После аварийного завершения (`.live`
PID мёртв) при старте предлагается восстановление. Штатное закрытие удаляет
journal/workspace; устаревшие `vector-pdf-*` и `.vector-*` очищаются.

## Сборка переносимого комплекта

`tools/package_windows.py` принимает embeddable ZIP CPython 3.12 x64, каталог
Windows-колёс, готовый лаунчер и путь результата. Сборка включает приложение,
тесты, tools, requirements, документацию, лицензии, SBOM и детерминированный
ZIP. Манифест содержит путь/размер/SHA-256 каждого файла и digest архива.

```powershell
python -m pip download --platform win_amd64 --implementation cp --python-version 3.12 --abi cp312 --only-binary=:all: -r requirements.txt -d wheels
curl.exe --fail --location --output python-embed.zip https://www.python.org/ftp/python/3.12.10/python-3.12.10-embed-amd64.zip
python tools/sbom.py --output release/sbom.json
python tools/package_windows.py python-embed.zip wheels VectorPDF.exe release/VECTOR-PDF-0.3.0-win-x64.zip --manifest release/manifest.json --sbom release/sbom.json
```

Лаунчер `tools/launcher_windows.c` собирается без CRT, с `/GS`, PE-манифестом
(`asInvoker`, `longPathAware`, PerMonitorV2, Win10/11) и VERSIONINFO 0.3.0.0.
CI использует `/GS /O2 /DYNAMICBASE /NXCOMPAT /HIGHENTROPYVA /MANIFEST`.

## Обновления

Релиз содержит четыре точных asset: архив, `.sha256`, `manifest.json` и
`manifest.json.sig`. Detached Ed25519-подпись проверяется по доверенному
публичному ключу до доверия полям manifest. Затем проверяются SHA-256 архива,
полный набор файлов, пути ZIP и обязательные компоненты. Staged runtime
проходит health-check; активируются `active`/`previous`; новая версия пишет
readiness token. При timeout/ошибке выполняется rollback, `--safe-mode` и
`--reset-update` отключают/сбрасывают обновление. Автоматическая установка по
умолчанию выключена.

Приватный ключ подписи в репозиторий не входит. Пока в `update_key.py` стоит
placeholder, обновления fail-closed; владелец должен выполнить
`tools/update_keygen.py` и подписать manifest через `tools/sign_manifest.py`.
